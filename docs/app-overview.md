# סקירת האפליקציה "חבורת מזכי הרבים" (mezakeharabim.com)

מצב: נובמבר 2026, גרסה 220. המסמך הזה ניתן לחברי מועצת ה-AI כרקע לכל דיון על האפליקציה.

## 1. למה האפליקציה קיימת
האפליקציה משמשת **משולחים** שאוספים צדקה ("מגבית") בלייקווד, ניו ג'רזי, ובערים שמסביבה: ג'קסון, טומס ריבר, האוול, בריק, מנצ'סטר ועוד.
המטרה שלה: לאסוף כמה שיותר עם כמה שפחות הליכה, ובלי שני משולחים באותו מקום באותו זמן.

היא עושה את זה בשני מישורים:
1. **מניינים בבתי כנסת.** מתי ואיפה יש מניין, ומי כבר "תפס" אותו לאיסוף.
2. **בית בית.** תכנון מסלול הליכה בין בתים, וחלוקת רחובות בין משולחים כדי שלא ידפקו פעמיים באותו בית.

המשתמשים הם ציבור חרדי. חלקם משתמשים בטלפונים כשרים בלי דפדפן, ולכן יש גם **ערוץ מייל** מלא, ובעתיד גם **קו טלפוני**.

## 2. מבנה טכני
- **שרת:** Cloudflare Worker אחד (`mezakeharabim-app`) עם מסד נתונים D1 (SQLite), בערך 100 טבלאות.
- **לקוח:** PWA בעברית ובאנגלית (`site/index.html`, `site/app.js`), עם Service Worker לעדכונים.
- **קבצים עיקריים** (כ-3.4MB קוד):

| קובץ | תפקיד | גודל |
|---|---|---|
| `site/_worker.js` | כל ה-API (כ-230 נקודות קצה), מתכנן בית בית, טבלאות | ‎700KB |
| `site/app.js` | הממשק הראשי | ‎440KB |
| `site/planner.js` | מתכנן מסלול בתי כנסת (`appPlan`, `dpRoute`) | ‎180KB |
| `site/walk.js` | מסכי בית בית | ‎130KB |
| `site/mailcore.js` + `src/mail.js` | ערוץ המייל: תפריטים, טפסים, ניתוח תשובות | ‎230KB |
| `site/covplan.js` | תוכנית כיסוי של כמה ימים | ‎45KB |
| `src/index.js` | נקודת הכניסה: fetch / email / scheduled, ותור המיילים MailQ | |
| `src/phone.js` | קו טלפוני (Telnyx). בנוי עד שלב התשלום, כבוי | |
| `site/i18n.js` | תרגום לאנגלית | ‎215KB |

- **פריסה:** ענף ← Pull Request ← מיזוג ← GitHub Actions פורס ל-Cloudflare. ב-PR שנוגע במייל רץ **סימולטור מיילים** (`tools/mailsim.mjs`, כ-19 תרחישים), על עותק לקריאה בלבד של הנתונים האמיתיים.
- **בדיקות:** כ-75 קבצי בדיקה (`test/*.test.mjs`), חלקם על נתוני לייקווד אמיתיים.
- **משימה מתוזמנת:** כל 10 דקות (מיילים שהגיע זמנם, משוב, הודעות לוח).
- **מגבלות:** עד 5 דקות CPU לבקשה (v218). מיילים נכנסים לתור (Durable Object `MailQ`, v219), כי Email Routing מוותר על מטפל שעובד זמן רב.

## 3. יכולות עיקריות

### 3.1 מניינים ובתי כנסת
- מאגר בתי כנסת וזמני מניינים (שחרית, מנחה, מעריב), לפי ימים.
- "📍 מה יש סביבי עכשיו", "🏛️ איפה יש הרבה מניינים" (שטיבלך לפי יום), ו"🚗 מה יש עכשיו קרוב" בזמן נסיעה.
- **אימות זמנים:** השוואה מול GoDaven ו-Click613, ובדיקת זמנים מאתרי בתי הכנסת (`sitetimes.js`).
- **צילום לוח זמנים:** OCR בעזרת AI שמגיע למנהל לאישור. ידוע שהוא עוד לא מבחין טוב בין לוח של יום ראשון ללוח של אמצע השבוע.
- **ספקות:** זמן שמחכה לבדיקה מסומן ❓ לכל מי שמגיע לאותו בית כנסת, ומנהל מכריע (✅ GoDaven נכון או ✅ קליק613 נכון).
- **תפיסת מניין למגבית:** מי אוסף איפה ומתי, כולל חלוקה "באמצע".

### 3.2 מתכנן מסלול בתי כנסת
`planner.js` בונה מסלול שעובר בכמה שיותר מניינים בכמה שפחות הליכה או נסיעה, וחוזר לבית הכנסת המרכזי.
בקשה פתוחה: מסלולי **הליכה** בין בתי כנסת. המשתמש יביא דוגמה למסלול גרוע.

### 3.3 בית בית
- העיר מחולקת ל**אזורים** ו**גושים** (`walk_blocks`, כ-1,000 גושים). כל גוש כולל רחובות, צדדים זוגיים ואי-זוגיים ומספרי בתים, ומפת רחובות להליכה (`walk_net`).
- **המתכנן** (`wPlan` ב-`_worker.js`): משולח בוחר אזור, יום ושעות, ומקבל מסלול. המסלול הולך בצורת נחש על שני צדי הרחוב, נכנס לרחובות ללא מוצא קצרים שנפתחים מהרחוב (סמטאות), נמנע מבתים שכבר תפוסים או נעשו, ממשיך מאיפה שהמשולח הקודם סיים, ולא מתחיל בבית בודד שאחריו הליכה.
  - v220: אחרי שהמסלול התחיל, הרחוב הבא לעולם לא רחוק יותר מ-400 מ׳ בקו ישר (`WALK_GAP_MAX_KM`).
- **תביעות** (`walk_claims`): מסלול שנלקח שמור למשולח, והבתים בו לא יינתנו לאחר.
- "✔ רשום": ברחוב מסומן דופקים רק בבתים הרשומים (`listed_homes`). יש גם "לא לדפוק" (DNK) ובתים מיוחדים ★ שאפשר לדווח עליהם.
- **פלט:** עמוד הדפסה `/p/<code>`, מפה כתמונה, PDF ומייל, עם הוראות פנייה ("פונים ימינה ל… והולכים כ-120 מ׳").
- **מדדים לבדיקה:** סקריפט שמריץ 4 משולחים ברצף על כל אזור ומודד בתים לשעה, דקות הליכה, ק"מ בלי בתים, ובתים שעברו לידם ולא דפקו.

### 3.4 ערוץ המייל (לטלפונים כשרים)
- כל פנייה מקבלת תפריט מלא (v215) בארבע קבוצות: 🧭 מסלולים, 📋 מה שלי, 🕍 מידע, 👤 החשבון שלי.
- כל כפתור הוא קישור mailto שפותח **מייל אחד עם כל השאלות**: שאלות ממוספרות ❶❷, אייקון לכל שאלה, אפשרויות ממוספרות, וסימן 👈 למקום התשובה (v217).
- התשובות נקראות גם כשמסנן מוחק סמלים. המערכת זוכרת תשובות חלקיות בין מיילים. AI משמש לזיהוי כוונה כשהטקסט חופשי.
- מסלול נשלח כמייל עם קישור לעמוד הדפסה.

### 3.5 עוד יכולות
חיפוש חברותא או שותף (`chav`), מידע נחוץ (`info`), חיזוק (טקסט ושמע), התראות Push, הזמנת חברים, משוב "היה שווה?", בקשות להצטרף לנסיעה (`ride_req`, טלפונים נחשפים רק אחרי אישור), ופאנל ניהול (אישורים, עריכות, גיבויים, מניינים לבדיקה).

## 4. עקרונות שהמשתמש (אברהם, המפתח והמנהל) קבע
- להספיק כמה שיותר בתים בכמה שפחות הליכה. אסור לשלוח משולח באמצע מסלול להליכה ארוכה בלי בתים.
- להיכנס לסמטאות ולרחובות ללא מוצא.
- לא להשאיר "שאריות" של בית-בית למשולח הבא.
- שינוי בנתוני האפליקציה רק באישורו. שום מפתח או סיסמה לא נכתבים בקוד או בצ'אט.
- ממשק פשוט בעברית. הוא לא מתכנת, ומבקש לא להטיל עליו פעולות טכניות.

## 5. נושאים פתוחים לדיון
1. **סמטאות במסלולי בית בית.** ניסיון לאסוף בתים "בדרך" עזר רק בחלק מהאזורים, ובאזורים מפוזרים (צפון, ג'קסון, האוול) הוא פירק רחובות לשאריות. הצעת המשתמש: להבחין בין אזורים צפופים (רידג' 32 בתים לק"מ, אוק/צ'סטנאט ופרוספקט/פיין 27) לבין מפוזרים (ג'קסון 15, טומס ריבר 18).
2. **מערכת נקודות ודרגות.** הבסיס אושר: נקודות לפי חשיבות המידע, דרגות 0, 50, 200, 500 ו-2000. עדיין לא הוחלט מה כל דרגה פותחת.
3. **מסלולי הליכה בין בתי כנסת.** ממתין לדוגמה.
4. **צילום לוח זמנים.** לזהות לוח של יום ראשון בנפרד מאמצע השבוע, ולאפשר יותר מתמונה אחת.
5. **השוואה שבועית ל-Click613.** ממתין לקובץ PDF.
